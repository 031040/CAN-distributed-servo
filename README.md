# CAN 分布式伺服控制系统（三节点 · STM32F103C8T6 ×3 + FreeRTOS）

三节点主从式分布式伺服：**一台纯主控（指挥官）+ 两台 PID 伺服从站**。主控板上不带电机，
只通过 CAN 把同一个目标位置广播给两台从站；每台从站各自读编码器、各自跑两级 PID 闭环
跟到目标——双电机分布式同步到位，从站本地闭环完全不依赖主控 CPU 的实时性。
从硬件接线、CAN 位时序推导到固件排障全部独立完成。

> 为什么用 CAN：控制周期固定（250 kbps 满载 4 ms/帧），远优于串口；
> 每台从站独立闭环，主控只下发"去哪"，不参与"怎么去"。

> 节点是参数化的：目标帧 `0x100+节点ID`、反馈帧 `0x200+节点ID`、滤波器、OLED 行全部
> 按 `NODE_COUNT` 数组化——**加第 N 台从站不改帧结构**，只加一个节点号 + 一个滤波器 +
> 一个数组槽。

工程都是 CubeMX 生成 + 在 USER CODE 区手写业务代码，**Keil MDK 打开
`MDK-ARM/V0_LED_1.uvprojx` 直接编译**（工程内部名沿用 CubeMX 默认名，与内容无关）。

## 系统架构（最终拓扑）

```
                         CAN 总线 250 kbps（120Ω 终端只在一端）
                                          │
        ┌─────────────────────────────────┼─────────────────────────────────┐
        │                                 │                                 │
 板D 纯主控 / 指挥官               板B 从站 #1                      板C 从站 #2
 STM32F103C8T6                    STM32F103C8T6                    STM32F103C8T6
 无电机 / 无编码器                 + 电机 #2 + 编码器               + 电机 #1 + 编码器
 TJA1050 收发器(5V)               SN65HVD230 (3V3)                SN65HVD230 (3V3)

 CommTask  串口控制台 pos <n>     ControlTask  20ms 两级 PID       （同 板B，NODE_ID=2）
 CANTask   10Hz 广播 0x101+0x102  CommTask     串口 5 值 CSV       过滤器只收 0x102
 DisplayTask OLED:S1/S2/TGT/CAN   CANTask      10Hz 反馈 0x201      反馈 0x202
 DiagTask  IWDG 喂狗 + 心跳       DiagTask     IWDG 喂狗 + 心跳
```

- 主控每 100ms 把 `g_target_position` 依次以 `0x101`、`0x102` 广播（两帧同值 = 双机同步指令）；
- 每台从站只收自己的 ID，跑 20ms 位置外环 + 速度内环 PID，把编码器跟到目标；
- 从站每 100ms 回 `0x201` / `0x202` 反馈（编码器位置 + 堵转状态位），主控用两个 filter bank
  精确匹配并分发到 `g_slave_pos[]`，OLED 两行实时显示 S1 / S2。
- 帧结构：目标与反馈都是 **2 字节 int16 LE + 1 字节 flags**，DLC=3。
  `flags bit0 = 使能`，`bit1 = 远程清堵转`——从站堵死后主控发一次 `pos` 即在线恢复，免下电。

## 固件角色映射

| 板 | 角色 | NODE_ID | 固件 | 负载 |
|---|---|---|---|---|
| 板 D（新板） | 纯主控 | 0 | `V9_CAN_master_3node` | 无电机；广播目标、收双从站反馈、OLED、控制台 |
| 板 B | 从站 #1 | 1 | `V9_CAN_slave_pid` | 电机 #2 |
| 板 C（原 2 节点主站） | 从站 #2 | 2 | `V9_CAN_slave_N2` | 电机 #1 |

两台从站电机控制脚逐字节相同（PWM=TIM3_CH1=PA6、方向 PA7+PB1、编码器 TIM2 PA0/PA1），
同一份从站代码跑在两块板上，行为一致。

## 关键设计点

- **纯主控剥离本机轴**：主控代码里没有编码器/PWM/堵转全局、没有 ControlTask——只有一个
  `g_target_position` 广播变量。风险面小，职责单一（下发命令 + 观测反馈）。
- **每从站一个 filter bank**：`mask=0` = 精确匹配。掩码位语义在 STM32 / GD32 克隆上相反，
  这个配置在两种硅上都安全（克隆上退化为全收仍能收到反馈），不会漏判好板——两节点踩坑里
  克隆芯片 CAN RX 物理报废的教训，见文末。
- **分布式同步 = 同广播目标 + 每从站本地独立闭环**：不靠主控算双电机位置差，两机天然同速
  同相（本地 PID 参数一致）。
- **从站堵转保护**：编码器测速≈0 且持续下令 1s → 锁存杀停，不依赖电流采样；主控带 bit1
  可远程解锁。
- **可观测性**：从站串口输出 5 值 CSV（`enc,pos,speed,tspeed,pwm`），主控串口是干净控制台
  （只有 `pos` 与链路 DBG 行）；上位机 `main_plot.py` 接任一台从站实时画跟随曲线。

### 为什么是 250 kbps 而不是 500 kbps

板子不用外部晶振，HSI 8MHz 直驱。8MHz ÷ 8 TQ/bit = 1 MHz bitrate 是理论极限，且 BS1/BS2
会跌破 CAN 规范"段长度 ≥2 TQ"的下限。实测 500 kbps 在真实总线上误码不可靠，**250 kbps 是
这个时钟树约束下的可靠上限**（Prescaler=4 / BS1=5TQ / BS2=2TQ，CubeMX 外手动算好写进代码）。

## 踩坑记录（最有含金量的排障）

### 克隆芯片 CAN RX 物理报废的鉴定

现象：**发送正常、永远收不到帧**。6 版固件全败——改滤波器、改中断、改轮询、换收发器都试过。
最后不是靠继续改软件，而是：

1. **对照实验**：同一份固件烧到另一块板，CAN 收发立刻正常 → 锁定是硬件（固件 6 版都没错）；
2. **寄存器回读实锤**：读调试接口 IDCODE 返回 0（非正品 STM32 特征），读 CAN FIFO 邮箱寄存器
   直接触发总线错误 → 判定克隆芯片，**CAN RX 物理报废**。

结论：换板重建，问题消失。滤波器这段的判断逻辑注释留在 `V9_CAN_master_3node/Core/Src/main.c`。

> 系统性排障先做**对照实验分清软硬件**，再谈改代码——反复改固件试运气是最低效的路径。

### 三节点阶段注意

- **主控板收发器接 5V 供电**：板 D 用 TJA1050（5V），RXD→PB8（5V-tolerant）、TXD→PB9
  （3.3V 进 5V 轨满足 VIH），VCC 必须取 5V 轨、共地；板 B/C 的 SN65HVD230 从 3V3 取电。
- **刷从站后 OLED 不驱动**：板 C 原是主站带 OLED，降级从站后其固件不 init OLED（黑屏属预期），
  靠 PC13 每帧闪 + 串口诊断；OLED 归主控板 D。
- **命令发给主控**：目标位置所有权在纯主控，`pos` 打到板 D 串口；打到从站串口只闪一拍就被
  广播覆盖。从站增益参数到各从站自己串口上调（协议无增益通道）。

## 上位机（tools/）

`main_plot.py`：串口读 5 值 CSV（`enc,pos,speed,tspeed,pwm`），matplotlib 实时画位置/速度曲线，
看超调与跟随误差。把串口接到**任一台从站**上：

```bash
pip install -r requirements.txt
python main_plot.py --port COMx
```

（`main.c` 开头 `OLED: OK` 等自由文本行会被上位机自动跳过，不影响 CSV 协议；主控串口的
`CAN DBG rx=/tx=` 同理被跳过。）

## 烧录与调试

- 编译器：Keil MDK5（工程自带 ARM Compiler 配置）
- 下载：ST-Link / SWD（PA13/PA14）
- 串口：USART1 57600 8N1，PA9 TX / PA10 RX
- 烧录顺序：先刷两台从站（板 B `V9_CAN_slave_pid`、板 C `V9_CAN_slave_N2`），再刷主控
  （板 D `V9_CAN_master_3node`）；上电后主控串口打印 `CAN 3-Node Commander Start` → `CAN: OK`，
  OLED 显示 `S1 / S2 / TGT` 三行，发 `pos 500` 双从站同步到位
- 调试注意：工程开着 IWDG（1s），**在线暂停超过 1s 会触发看门狗复位**，喂狗点分散在 DiagTask

## 复现

硬件：蓝板 STM32F103C8T6 ×3（板 D/B/C）、CAN 收发器 ×3（板 D：TJA1050 5V；板 B/C：
SN65HVD230 3V3）、JGA25-370 电机 + TB6612 驱动 ×2、SSD1306 OLED ×1。三块板子 CAN 共地，
终端电阻只在一端接 120Ω；两个 TB6612 的 VM 各用独立 5V 源（双电机堵转电流大，单路会掉压）。

流程：见「烧录与调试」。转任一从站电机轴，主控 OLED 对应行同步显示；`pos 500` 双电机同时到位；
堵转一台 → OLED 该行 `STALL` → 松手后发一次 `pos` 在线恢复。
