# CAN 分布式伺服控制系统（STM32F103C8T6 ×2 + FreeRTOS）

主从式分布式伺服：主站通过 CAN 广播目标位置，从站两级 PID 闭环跟随，
双电机同步到位。从硬件接线、CAN 位时序推导到固件排障全部独立完成。

> 为什么用 CAN：控制周期固定（250 kbps 满载 4 ms/帧），远优于串口；
> 双机各带编码器，从站本地闭环不依赖主站 CPU 实时性。

> **三节点版**：本仓库还含纯主控拓扑——`V9_CAN_master_3node`（板 D **纯指挥官**，
> 不托管本机电机轴，只广播目标 + 收两从站反馈）+ `V9_CAN_slave_N2`（板 C
> 从站 #2）+ `V9_CAN_slave_pid`（板 B 从站 #1）= 一台纯主控 + 两台独立 PID
> 伺服从站同播同步。2 节点版（主站自带一轴 + 单从站）原样保留在上两个工程。

## 目录结构

```
.
├── V9_CAN_master      主站工程（NODE_ID=0，广播目标、接收从站反馈）
├── V9_CAN_slave_pid   从站工程（NODE_ID=1，两级 PID 闭环 + 堵转保护）
├── V9_CAN_master_3node 三节点版纯主控（板 D，NODE_ID=0，无本机电机轴）
├── V9_CAN_slave_N2     三节点版从站 #2（板 C，NODE_ID=2）
├── V10_Snake          早期项目：OLED 贪吃蛇 + 编码器旋钮（复用了同一套外设）
├── docs/              技术博客 ×2 + 调试踩坑笔记 ×2
└── tools/             Python 上位机（串口曲线实时绘制）
```

三个工程都是 CubeMX 生成 + 在 USER CODE 区手写业务代码，**Keil MDK 打开
`MDK-ARM/V0_LED_1.uvprojx` 直接编译**（工程内部名沿用了 CubeMX 创建时的
默认名，与内容无关）。时钟铁律：**HSI 8MHz 直驱，不碰 HSE/PLL/72MHz**。

## 系统架构

```
+----------------------+        CAN 总线 250 kbps        +----------------------+
|  板A 主站 master      | <-----------------------------> |  板B 从站 slave       |
|  STM32F103C8T6       |                                 |  STM32F103C8T6        |
|                      | 0x101 目标位置(2B LE + 1 flags) |                       |
|  FreeRTOS            | 0x201 编码器反馈(2B LE + 1 stat)|  FreeRTOS             |
|  ControlTask  20ms   |                                 |  ControlTask  20ms    |
|  CommTask    串口    |                                 |  CommTask    串口     |
|  DiagTask    喂狗    |                                 |  DiagTask    喂狗     |
|  DisplayTask OLED    |                                 |  CANTask     10Hz     |
|  CANTask     10Hz    |                                 |                       |
+----------------------+                                 +----------------------+
    JGA25-370 电机 #1（TIM2 编码器 + TIM3 PWM）             JGA25-370 电机 #2
```

协议：`0x100 + 节点ID` 为从站目标帧，`0x200 + 节点ID` 为反馈帧，DLC=3。
flags bit0 = 使能，bit1 = 远程清堵转（从站堵死后主站发一次 "pos" 命令即可
在线恢复，不用下电）。扩容加节点不需要改帧结构。

## 关键数据（实测可复现）

| 项目 | 值 | 说明 |
|---|---|---|
| 双电机到位 | 主站 503 / 从站 499 @ 目标 500 | 误差 <1% |
| CAN 位时序 | 250 kbps，8 TQ/bit，采样点 75% | HSI 8MHz 直驱推导，见下 |
| 控制周期 | 位置环 + 速度环双层，20 ms | 位置外环 P + 速度内环 PID |
| 堵转保护 | 编码器测速≈0 持续 1s → 杀停 | 不依赖电流采样 |
| 故障注入 | 拔线 → 从站保持、主站报链路断 → 插线自愈 | 计数器冻结判断，无软件复位 |
| IWDG 浸泡 | 5 分钟零复位 | 1s 看门狗，DiagTask 唯一喂狗者 |
| 可观测性 | 串口 57600 8N1 + OLED 双板同屏 | 5 值 CSV 实时曲线 |

### 为什么是 250 kbps 而不是 500 kbps

板子不用外部晶振，HSI 8MHz 直驱（1 MHz 振荡器没有，HSE/PLL 全不碰）。
8MHz ÷ 8 TQ/bit = 1 MHz bitrate 是理论极限，且 BS1/BS2 会跌破 CAN 规范
"段长度 ≥2 TQ"的下限。实测 500 kbps 在真实总线上误码不可靠，**250 kbps
是这个时钟树约束下的可靠上限**，位时序参数（Prescaler=4 / BS1=5TQ /
BS2=2TQ）是在 CubeMX 外手动算好写进代码的。

## 踩坑记录（最有含金量的排障）

### 克隆芯片 CAN RX 物理报废的鉴定

主站现象：**发送正常、永远收不到帧**。6 版固件全败——改滤波器、改中断、
改轮询、换收发器，全试过。最后不是靠继续改软件，而是：

1. **对照实验**：同一份固件烧到另一块板，CAN 收发立刻正常 → 锁定是硬件
   （固件 6 版都没错）；
2. **寄存器回读实锤**：读调试接口 IDCODE 返回 0（非正品 STM32 的特征），
   读 CAN FIFO 邮箱寄存器直接触发总线错误 → 判定手上这块是克隆芯片，
   **CAN RX 物理报废**。

结论：换板重建主站，问题消失。这版固件里有完整的注释记录这次的判断
逻辑（见 `V9_CAN_master/Core/Src/main.c` 里 CAN 滤波器配置那一段）。

> 这次排障的最大收获：**系统性问题先做对照实验分清软硬件，再谈改代码**。
> 反复改固件去试运气是最低效的路径。

## 三个工程说明

| 工程 | 角色 | 要点 |
|---|---|---|
| V9_CAN_master | 主站 | NODE_ID=0；CAN 滤波用掩码匹配 0x201（掩码语义在 STM32/GD32 克隆上相反，这个配置在两代硅上都能过，注释里有完整说明） |
| V9_CAN_slave_pid | 从站 | NODE_ID=1；两级 PID + 堵转保护 + 编码器测速；CAN 滤波只收自己的 0x101 |
| V10_Snake | 早期项目 | OLED 贪吃蛇，编码器旋钮交互；16×7 棋盘、200ms 转向锁存防抖、LCG 伪随机食物、SSD1306 脏页刷新 |

成长线：V10 和 V9 用的是**同一个编码器外设**——大二拿它做游戏旋钮输入，
大四把它升级成电机测速闭环反馈，从"输入"到"控制"。

## 上位机（tools/）

`main_plot.py`：串口读 5 值 CSV（`enc,pos,speed,tspeed,pwm`），matplotlib
实时画位置/速度曲线，调 PID 时看超调、看跟随误差。运行：

```bash
pip install -r requirements.txt
python main_plot.py --port COMx
```

（`main.c` 里开头打印的 `OLED: OK` 等自由文本行会被上位机自动跳过，
不影响 CSV 协议。）

## 烧录与调试

- 编译器：Keil MDK5（工程自带 ARM Compiler 配置）
- 下载：ST-Link / SWD（PA13/PA14）
- 串口：USART1 57600 8N1，PA9 TX / PA10 RX
- 调试注意：工程开着 IWDG（1s），**在线调试暂停超过 1s 会触发看门狗复位**，
  喂狗点分散在 DiagTask，调试时建议先关 IWDG 或按住停止点

## 复现

硬件：蓝板 STM32F103C8T6 ×2、SN65HVD230 CAN 收发器 ×2、JGA25-370 电机
+ TB6612 驱动 ×2、SSD1306 OLED ×1。两台板子 CAN 收发器共地，终端电阻
只在一端接 120Ω。

流程：先编译烧录从站、再烧主站；上电后主站串口会打印 `CAN: OK`，OLED
显示 `CAN OK <n>`（n 随帧数增长）；转从站电机轴，主站 OLED 同步显示
从站编码器位置。发 `pos 500` 双电机同时到位。
